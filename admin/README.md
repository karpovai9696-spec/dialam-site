# Админ-панель Dialam (прототип)

Единая админ-панель для управления контентом четырёх брендов/сайтов:

1. **Диалам+** — сеть центров гемодиализа (Волжск, Йошкар-Ола, Орёл, Нижневартовск);
2. **Консалтинговая компания**;
3. **Диамедика**;
4. **Салюшенс**.

Модель расширяемая: новые сайты, филиалы и элементы контента добавляются
через интерфейс без изменения схемы БД (универсальная таблица `items` с JSON-полем).

## Запуск

Требуется Python 3.11+. Внешних зависимостей нет (только стандартная библиотека).

```bash
python admin/server.py --port 8090
# открыть http://127.0.0.1:8090/
```

Пароль администратора задаётся переменной окружения `ADMIN_PASSWORD`
(по умолчанию — `admin123`):

```bash
ADMIN_PASSWORD='secret' python admin/server.py --port 8090
```

При первом запуске создаётся база `admin/data/admin.db` и заполняется seed-данными
(реальные реквизиты ООО «Диалам+»: ИНН 1215211807, ОГРН 1161215058400,
лицензия ЛО-12-01-001016 от 16.05.2019, dialam@list.ru, +7 (958) 843-20-66,
ул. Анникова, 4а, пом. 7; 4 филиала; лицензии, новости, вакансии, сотрудники,
услуги, документы, key/value настройки). Остальные три бренда — сайты-заглушки,
наполняются через панель.

Чтобы начать «с чистого листа», удалите файл `admin/data/admin.db` и перезапустите сервер.

## Структура

```
admin/
├── server.py          # HTTP-сервер + SQLite API (stdlib only)
├── data/admin.db      # база (создаётся при первом запуске, в .gitignore)
├── exports/           # файлы экспорта <slug>.json (в .gitignore)
└── static/            # SPA: index.html, css, js, локальные шрифты Onest (woff2)
```

## API

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/login` | `{password}` → HttpOnly cookie сессии |
| POST | `/api/logout` | завершение сессии |
| GET | `/api/me` | проверка авторизации |
| GET/POST | `/api/sites` | список / создание сайтов |
| GET/PUT/DELETE | `/api/sites/<id>` | карточка сайта |
| GET | `/api/sites/<id>/items?type=news` | элементы контента |
| POST | `/api/sites/<id>/items` | создать элемент |
| PUT/DELETE | `/api/items/<id>` | изменить / удалить элемент |
| GET | `/api/sites/<id>/export` | полный JSON сайта |
| POST | `/api/sites/<id>/export-file` | сохранить `admin/exports/<slug>.json` |
| GET | `/api/public/sites` | активные сайты (без авторизации) |
| GET | `/api/public/sites/<slug>.json` | публичный JSON (CORS `*`) |
| GET | `/api/health` | проверка работоспособности |

Типы элементов (`items.type`): `branch`, `license`, `news`, `vacancy`, `staff`,
`service`, `document`, `setting`. Схема полей каждого типа описана в `server.py`
(`ITEM_TYPES`) и в интерфейсе панели.

Ошибки возвращаются как JSON `{"error": "...", "code": N}` с кодами 400/401/404/500.

## Безопасность (уровень прототипа)

Реализовано:

- пароль только из env (`ADMIN_PASSWORD`), сравнение через `secrets.compare_digest`;
- сессии хранятся в памяти сервера, cookie `HttpOnly; SameSite=Lax`;
- экранирование HTML при выводе данных в JS (`esc()`);
- защита статики от path traversal; `admin/data/` и `admin/exports/` не отдаются;
- пароли не логируются.

**Для продакшена необходимо доработать:**

- HTTPS (TLS-терминация, `Secure` flag у cookie);
- полноценные пользователи, роли и хеширование паролей (bcrypt/argon2 вместо env);
- CSRF-защита (токены или `SameSite=Strict` + проверка Origin);
- хранение сессий в постоянной памяти (БД/Redis) и их инвалидация при рестарте сервера;
- ограничение частоты запросов (rate limiting) и защита логина от брутфорса;
- резервное копирование `admin/data/admin.db` и регулярный экспорт в `admin/exports/`;
- публикация публичного JSON на CDN/сайте только после ревью.
