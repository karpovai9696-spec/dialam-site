# Правила распределения задач между Gemini, DeepSeek и Qwen

Правила распределения задач между браузерными моделями (по опыту проекта dialam-site).

Gemini — аналитик и архитектор:
- большой контекст, ТЗ, разбор нескольких файлов, сложные баги, риски;
- юридические и медицинские тексты, UX-копирайт;
- финальная проверка решений. Не отдавать мелкие механические правки.

Qwen Coder — исполнитель:
- маленькие патчи в 1-2 файлах, формы, таблицы, фильтры, CSS, seed, повторяющиеся правки;
- нужно давать точные пути файлов, критерии приёмки и запрет добавлять лишние файлы;
- требует проверки: может написать «готово», не изменив нужный файл.

DeepSeek — независимый инженер-ревьюер:
- проверка патчей, поиск пропущенных кейсов, алгоритмы, SQL, регулярки, тесты;
- быстрые черновики и второе мнение;
- не использовать как источник фактов без проверки.

Рабочая схема:
1. Gemini пишет ТЗ и критерии.
2. Qwen делает маленький патч.
3. DeepSeek проверяет патч и тесты.
4. Оркестратор применяет, проверяет git diff и запускает тесты.
